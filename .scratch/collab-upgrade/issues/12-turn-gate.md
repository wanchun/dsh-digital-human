# 12 · 回合独占与邮箱：要不要搬 turn-gate

Type: grilling
Status: resolved
Blocked by: 04

## Question

同一条会话被两路同时投递时，谁来保证"一次只有一个回合在跑、消息不丢、按停止后不复活"？

## 现状

- 插件没有锁：投递直接进 `sessionController.prompt`，靠 DSH 的 `steer` / `followup` 语义兜（`src/lib/chat.ts:665-678`）。
- 基线 15 条缺口里的第 14 条："并发/租约（多派活同时打一个数字人）——无锁"。
- 实测地址漂移（见 11）会让"两条线程打同一会话"从理论问题变成常态。

## Halo 的做法（`main/platform/turn-gate/index.ts`，543 行，零 Electron 依赖）

- 邮箱 FIFO，上限 128，满了抛错而不是静默丢（`:79,203-210`）。
- `identity + coalescingKey`：同组同键折叠（新替旧）；跨越 relayed 屏障不折叠（`:186-203`）。
- `deliverMidTurn` 原子接收，失败退回缓冲（`:401`）。
- `park / putBack`：人按停止 → 该会话冻结，期间不启动不并入，只留"被取回"的消息。
- `reservationTtlMs` 看门狗：占了位却没有回合，超时回收，防槽位泄漏（`:127-155`）。

## 可选

- **A 搬 turn-gate**：整段复用，按 (数字人, 会话) 建槽位。
- **B 只做最小独占**：一个内存 Set + 队列，够用就好（约 100 行）。
- **C 不动**：依赖 DSH 的 steer/followup。

➡️ 推荐 B。理由：A 解决的三件事里，"同键折叠"和"park"你的场景用不到；而"独占 + 队列 + 停止后不复活"三件，100 行能写完，还能顺手和 04 的任务行共用一套状态。
## 04 关闭后的变化

04 已经定下：同会话最多一条 `in_progress` + 队列 + 一轮结束投递队首 + 按所有者关闭。

这**已经是最小独占**。所以本单剩的真问题只有两个：

- `park`（人按停止后冻结会话）要不要？现在没有这个语义，停止只是取消当前回合。
- 槽位泄漏要不要看门狗？04 的启动清扫覆盖了重启场景，但没覆盖"回合一直不结束"。

➡️ 若 04 落地，本单大概率在 10（排序）里被并进去，而不是单独立项。
## Answer

**不搬 turn-gate，并入 04。**

04 已经定了最小独占的全部要素：

| turn-gate 的机制 | 04 的对应 |
|---|---|
| 会话独占 | 同会话最多一条 `in_progress` |
| 邮箱 FIFO（128） | 队列 + 队首投递 |
| 槽位泄漏看门狗 | 启动清扫（`in_progress` 但会话空闲 → `stopped(restart)`） |
| `coalescingKey` 折叠 | **不做**：没有推送合并场景 |
| `park`（人按停止后冻结） | **不做**：停止只取消当前回合，不冻结会话 |

**不做 `park` 的理由**：它解决的是「用户按了停止，但队友的消息还在陆续到达」。你的停止来自派单方，且 04 的 `cancel` 已经是显式意图。

**重新开单条件**：出现「停止之后又被旧消息唤醒」的实测问题。

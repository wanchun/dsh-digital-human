# 06 · 上下文：要不要接管 compaction

Type: grilling
Status: resolved

## Question

长会话的上下文，继续用 DSH 原生压缩，还是像 ds-bot 那样接管？

## 现状

- DSH `dsh-compaction-basic`：按 token 压力把最旧历史压成摘要，保留最近一截（`thresholdRatio 0.8`、`retainRatio 0.16`），溢出后压缩重试。
- ds-bot：**关掉原生**，自己一套——steward 读最近消息判 `switch`（工作告一段落，开新 part + 交接笔记）还是 `compact`（就地压缩接着干）；checkpoint 里用户的话逐字保留；全文 FTS 可回查。

## 可选

- **A 只调参**：给长跑的数字人（研发/自测）单独设 `modelPolicies`，多留近期消息。
- **B 加交接文档**：重要上下文落 `memory/`，会话开头注入"上次到哪了"，不动压缩。
- **C 完全接管**：复刻 steward 的 switch/compact 判据。

➡️ 推荐 A → B。C 的收益在"跨会话接力"，而那件事 B 用文件就能做，不必接管压缩。
## 侦察补充

Halo **不接管压缩**：它靠"开局快照 + 注入预算 + 之后用 Read/Grep 检索"控制上下文（`snapshot.ts:1-6`、`section.ts:44-63`）。

➡️ **修订**：两条路都说明"接管压缩"不是必选项。ds-bot 接管，是因为它要"换段"，而换段是为了让人格有任期。先做 07 的注入预算，比动压缩便宜一个数量级。
## Answer

**结论：什么都不做，但有依据。**

- **不接管压缩**。没有「换段」需求；ctx.compaction 有正规接缝，但自定义摘要模板的收益小于跟着 DSH 版本走的成本。
- **不动阈值**（0.8 / 0.16）。配置是 per-model 不是 per-session，动了会波及同一模型的所有会话。
- **「当前任务」靠 # now 锚定**（07 的 16KB 预算），不写额外 handoff——handoff 是给「换段」设计的，这里没有换段。
- **不提供被压缩历史的检索**。信箱 200 条 + # History 时间线 + memory_status 够用，等真出现「想不起三周前」再上。

**事实依据**：DSH 的压缩只替换较旧的区间，最近历史原样保留，最新那条消息不会进摘要——所以 ds-bot 那个「摘要把没答的问题答掉」的结构性缺陷在这里不成立。

**重新开单的条件**（任一出现）：
1. 数字人压缩后明显重复劳动或丢失任务线索；
2. 需要「人格任期」（一个数字人跨多个 Session 续命）。

**与 07 的耦合（重要）**：本单把锚押在 # now 上，因此 07 的行截断必须保留最新内容（尾部），否则 # now 被截掉最新状态，「靠 # now 锚定」就失效。

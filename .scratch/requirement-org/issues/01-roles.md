# 01 · 职责矩阵与调度链

Type: grilling
Status: resolved

## Question

五个角色各自做什么、拒绝做什么、谁调度谁。要定到"能直接写进 persona"的粒度。

提议（待确认）：

| 角色 | 做 | 拒绝 |
|---|---|---|
| PM | 对外沟通、需求接入与建档、决定"这是不是新需求"、把需求交给负责人、收负责人汇报 | 不碰代码、不碰流水线、不直接调度开发/自测/部署 |
| 研发负责人（一需求一记录一会话） | 该需求的进度、资料、修复环；调度开发/自测/部署；对 PM 汇报 | 不亲手写代码、不亲手部署 |
| 开发助手（一需求一记录一会话） | A 开发 / B 合并 / C 验证 / F 冒烟，调千手执行 | 不派自测、不派部署、不做需求接入 |
| 自测助手（一记录、一会话服务 N 需求） | 按派单执行 E | 不派活、不判定上线 |
| 部署助手（一记录、一会话服务 N 需求） | 按派单执行 D（测试环境） | 不派活、不碰生产 |

要确认的点：
1. "一个需求一个" 落在记录还是会话？（当前判断：会话；记录各一条）
2. 负责人是否也一需求一条记录？还是记录一条、会话多开？
3. 自测/部署是**一条记录**（单会话）还是**一条记录多会话**？——直接决定记忆隔离怎么做。
4. PM 与负责人之间是不是严格一对一（一个负责人只服务一个需求）？
## Answer

五角色，会话粒度按"谁会被长任务占住"来分：

| 角色 | 记录 | 会话 | 理由 |
|---|---|---|---|
| PM | 1 条 | 1 个（对外一个） | 只跟人说话 |
| 研发负责人 | 1 条 | **一需求一个**（thread 模式） | 需求级进度/资料/修复环 |
| 千手开发助手 | 1 条 | **一需求一个**（thread 模式） | 千手任务耗时长，必须按需求分开，互不阻塞 |
| 自测助手 | 1 条 | **1 个**（single 模式） | 横向服务 N 个需求，靠子 agent 并发 |
| 部署助手 | 1 条 | **1 个**（single 模式） | 同上 |

**后果一**：记忆隔离只对"一需求一会话"的两条（负责人、开发）有意义；自测/部署只有一份记忆，必须**只放机制**，需求状态放账本与版本目录。

**后果二**：single 模式下所有线程名都会落到同一个会话，**账本的 `conversation` 字段失去区分力**——自测/部署的工作项必须自带 `requirement`。

**后果三**：派单必须同时带 `requirement`（需求标识）与线程名；回执也要带，否则分不清是哪条需求。

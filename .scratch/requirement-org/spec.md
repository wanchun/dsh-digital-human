# 设计 · 需求级数字人组织（完整版）

> 状态：定稿中（4/10 工单已关）。实施前以本文件为准；工单是它的推导过程。

## 1. 目标

把"一个全能数字人按需求串行干活"改成"按需求装配的小组"：

- **PM**：唯一对外，需求接入、身份判断、归档与召回。
- **研发负责人**：一个需求一个会话，掌握该需求的资料、进度、修复环，调度下面三个执行者。
- **千手开发助手 / 自测助手 / 部署助手**：各一个需求一个会话，只执行，不派活。

## 2. 非目标

生产部署与上线、上线检测的判定角色、改 pace/qs 平台、多租户权限隔离。

## 3. 角色与拓扑

```
人（组长/产品/测试）
  └─ PM（多会话：一个聊天一个）
       └─ 研发负责人[需求 A] ─┬─ 开发助手[需求 A]
                              ├─ 自测助手[需求 A]
                              └─ 部署助手[需求 A]
```

| 角色 | 记录 | 会话键 | 调度权 | 绑 bot |
|---|---|---|---|---|
| PM | 1 条 | **聊天地址**（`direct:<id>` / `group:<id>`，dsh-im 建） | 派负责人 | 是 |
| 研发负责人 | 1 条 | 线程名 | 派开发/自测/部署 | 否（由 PM 代问） |
| 开发助手 | 1 条 | 线程名 | 无 | 否 |
| 自测助手 | 1 条 | 线程名 | 无 | 否 |
| 部署助手 | 1 条 | 线程名 | 无 | 否 |

## 4. 会话模型

- **线程名**（`conversation_id`）是需求主键，格式由**人设**决定，插件只要求唯一、稳定。
- 首次用某个线程名派单时，插件自动建会话；之后复用（`chat.ts#create` 已实现）。
- PM 的会话由 dsh-im 按聊天创建，插件不干预。
- 一个需求因此有 **4 个执行会话**（负责人 / 开发 / 自测 / 部署）。**PM 的会话按聊天复用**，不随需求增长，也不参与需求归档。

## 5. 记录级开关

`config.json` 新增两个开关，缺省保持旧行为：

| 开关 | 取值 | PM | 四个执行角色 |
|---|---|---|---|
| `sessionWorkspace` | `record` / `requirement` | `record` | `requirement` |
| `memoryScope` | `record` / `session` | `record` | `session` |

**这两个开关是本次插件改动的总闸**：全关 = 今天的行为，一条不变。

## 6. 工作区布局

```
<工作区>/
  project-info.md            # 项目/子系统/环境/流水线（跨需求，基座）
  project-list.md            # 需求总表：只做索引，一行一需求
  reqs/<线程名>/             # 一个需求一个目录，四个执行会话共用 cwd
      docs/                  # brief.md / progress.md / nodes/ / 证据
      code/<repo>/           # git worktree，只读分析用
  _archive/<线程名>/          # 上线后整体移入，保留 docs，删 code
  _archive/index.md          # 归档索引（PM 维护，恢复的唯一凭据）
  .locks/<子系统>@<环境>/     # 部署互斥锁（全局，跨需求）
```

多仓库需求：`code/<repo1>/ code/<repo2>/`。

## 7. 记忆模型

```
humans/<id>/memory/
  _shared.md              # 跨需求：Patterns / Errors / 团队规矩（预算 4KB）
  <线程名>.md              # 该需求的工作记忆（预算 16KB）
  <线程名>/<时间>.md        # 该需求的历史归档
```

- 注入：当前会话那份 + `_shared` 常青段；`sessionScope: record` 时退回旧行为（读 `memory.md`）。
- 压缩、归档按文件独立，互不影响。
- 迁移：现有 `memory.md` 整份降级为 `_shared.md`，不强行拆分。

## 8. 账本模型

- 工作项仍按记录存 `tasks.jsonl`；`conversation` 恒等于线程名（无单会话角色），**天然按需求可分**。
- 状态机不变：`queued → in_progress → done|failed|stopped|blocked|cancelled`。
- 升级沿派单链：执行者失败 → 通知派单方（负责人）；负责人失败 → 通知 PM；PM → 人。
- 定位：账本是**事实来源**，消息只带指针（任务 id + 线程名）。

## 9. 派单契约

**PM → 负责人**（首条消息即建档）：

```
线程名、需求号/DPMS、项目、子系统（可多个）、版本、目标环境、
验收口径、版本目录路径、触发人
```

**负责人 → 执行者**：同一线程名 + 工作项 id + 具体任务（开发/自测/部署）+ 目标环境。

**回执**：执行者 → 派单方，带任务 id、结论、证据路径；失败必带归因。

**禁止**：执行者自行派活；跨角色跳级（PM 直接派开发）。

## 10. 部署机制

- **互斥**：`mkdir .locks/<子系统>@<环境>`，失败即"已被占用"；终态释放；崩溃按 triggerId 复查回收。
- **触发前记基线**：`lastestTrigger.id/date`，轮询后必须比对，避免把上次 SUCCESS 当本次。
- **首轮确认**：键 = 子系统+环境+版本；部署人回 `needs-confirm`，PM 用现有 bot 问触发人，确认后重派带 `confirmed: true`。
- **子 agent**：全部执行交给子 agent，每 (子系统,环境) 一个，≤4；子 agent 禁用 `digital_human_send`/`notify_bot`；只回结论 + 指针。
- **只发测试环境**；缺 `idc` 或缺 `version` 直接拒绝。

## 11. 归档与召回

**归档**（PM 在上线检测 OK 后）：

1. 记下该需求 **4 个执行会话**的 id（不含 PM 的聊天会话）；
2. 逐个 `workspaceController.archiveSession({ sessionId, stopActivity: true })`；
3. 目录 `reqs/<线程名>/` → `_archive/<线程名>/`；
4. `git worktree remove` 删除 `code/`；
5. 往 `_archive/index.md` 追加一行。

**索引格式**：

| 需求 | 线程名 | 执行会话 id（4 个） | 归档时间 | 结论 |
|---|---|---|---|---|

**召回**：查索引 → 目录移回 → 逐个 `unarchiveSession` → 会话原样恢复（上下文完整）。归档会话收消息会被 `blocked`，所以必须先 unarchive。

## 15. 验收（沙箱）

1. 开关全关 → 行为与今天完全一致（回归基线）。
2. `sessionWorkspace: requirement` → 新线程名自动建 `reqs/<线程名>/`，两个线程名互不干扰。
3. `memoryScope: session` → 两份记忆互不可见，`_shared` 都可见；归档按线程名分目录。
4. 描述注入 → PM 提示词里出现同伴职责。
5. 链路 → PM 派负责人 → 负责人派部署（桩命令）→ 回执带同一线程名。
6. 归档/召回 → 归档后目录与索引正确，unarchive 后会话可继续。

## 16. 风险

| 风险 | 处置 |
|---|---|
| 插件改动影响现网 | 开关缺省旧行为；沙箱先验；生产重启由人确认 |
| 会话数增长 | 上线归档 + 索引；归档后必须先召回才能派单 |
| 记忆迁移丢失 | 整份降级为 `_shared`，可回滚备份 |
| worktree 污染仓库 | 归档时 `git worktree remove` |
| 负责人成为新瓶颈 | 一个需求一条会话，天然并行；执行者按需求分会话 |

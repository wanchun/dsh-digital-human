# 02 · 首轮确认的粒度

Type: grilling
Status: resolved

## Question

"同一版本第一次确认，之后自动"——要把它写成可执行的规则，得先定三件事：

1. **确认的键**：按「子系统+环境+版本」？还是按「版本」一次确认覆盖所有环境？还是按「需求工作项」？
2. **谁来确认**：触发人（你）私聊过 bot，还是有固定的测试群？确认走 `notify_bot` + 回复，还是走工作项升级？
3. **确认的失效**：同一版本修复环重发（D 部署可能跑 2–3 次）算不算"后续"，直接自动？换环境要重新确认吗？

## 现状

- 插件已有升级机制：工作项 failed/blocked/超时 → 私聊 owner；5 分钟内折叠。
- 部署人绑 bot 后才有 `notify_bot`；未绑时只能在自己的会话里回。

➡️ 推荐：键 = **子系统+环境+版本**；确认人 = **触发人**（私聊）；同一键确认过就自动重发（含修复环），换环境或换版本重新确认。
## Answer

- 键 = **子系统 + 环境 + 版本**（换环境或换版本重新确认；同一键含修复环重发不再问）。
- 确认人 = **触发人**；由 **PM 用现有 bot** 发问（部署人回 `needs-confirm`，PM 问完重派并带 `confirmed=true`）。
- 部署人不绑新 bot。

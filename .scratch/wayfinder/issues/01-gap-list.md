## Question

把生产 3 个角色人设的每一节，逐条对到新的 6 个角色上。


## Resolution

### 生产 PM（14 节）→ 新 PM

| 生产章节 | 新 PM | 判定 |
|---|---|---|
| 角色 | 有 | 已承接 |
| 核心准则 | 有（9 条） | 已承接 |
| 配置读取 | 有 | 已承接 |
| 技能使用（单一权威） | 无 | 有意不做（人设即权威） |
| 通知通道纪律 | 核心准则第 3 条 | 部分承接（chatId 取值顺序有，留痕未写） |
| 核心文档 | 两张表 | 有意简化（三张并两张） |
| 仓库分析前置纪律 | 有 | 已承接 |
| 职责一 项目信息表与成员登记 | 有 | 已承接 |
| 职责二 会话接入 | 有 | 已承接 |
| 职责三 需求评估与把关 | 有 | 已承接 |
| 职责四 日常解答 | 有 | 已承接 |
| 职责五 建档 | 有（工具） | 已承接 |
| 职责六 移交 | 有（派单） | 已承接 |
| 职责七 中转 A/B/C | 有 | 已承接 |
| 写入与记忆纪律 | 有 | 已承接 |
| 沟通风格 | 有 | 已承接 |
| 通知纪律硬性 | 有 | 已承接 |
| 自测/排障转介 | 有（转负责人） | 已承接，改了去向 |

### 生产开发（17 节）→ 新开发 / 新负责人

| 生产章节 | 去向 | 判定 |
|---|---|---|
| 核心定位 | 开发 | 已承接（远程任务操作员） |
| 配置读取 | 开发 | 无意识遗漏 |
| 技能使用 | — | 有意不做 |
| 本地仓库同步纪律 | — | 不适用（不本地开发） |
| 触发方式 | 开发 | 部分承接（只有派单，无触发条件） |
| 扫描流程 | 开发 | 无意识遗漏 |
| 与 PM 协作 | 开发 ↔ 负责人 | 已承接（换成负责人） |
| 与自测协作 | 负责人 | 无意识遗漏（谁派自测、怎么交接） |
| PM 消息处理 | — | 不适用（开发不接 PM） |
| 结果/阻塞上报 A/B/C | 负责人 | 已决定：执行者只报结论+证据，负责人组装 |
| project-list 维护 | PM | 已承接 |
| 单需求推进 | — | 不适用（一需求一会话天然隔离） |
| 轮询与纪律 | 负责人 | 已决定：上限由负责人派单时给，超时由它判 |
| 禁止事项 | — | 人为不做（本轮） |
| 写入纪律 | 六角色 | 已承接（写入归属） |
| 沟通风格 | — | 无意识遗漏 |
| 等待与任务归属 | 开发 | 已承接（挂起转一句问句，判断归负责人） |

### 生产自测（1 节）→ 新自测

| 章节 | 判定 |
|---|---|
| 发布后自测（节点 E） | 已承接且更厚 |

### 生产没有、新角色新增

- 研发负责人：把生产的「PM 编排 + 开发的推进」拆出来独立成角色。
- 部署执行、上线准备：生产没有对应角色，全新。

### 结论（三条待补）

1. **开发缺三节**：配置读取、扫描流程、沟通风格——都不致命，可后补。
2. **缺一条交接**：负责人怎么派自测、自测怎么回（生产的「与自测协作」节）。
3. **通知留痕**：PM 每次通知要在 progress 留痕（chatId 来源 + 内容摘要）。

## Question

两个角色怎么切、bug 怎么进来怎么回流、召回后会话怎么处理。

## Resolution

### 链路（完整）

```
开发 → 合并 → 验证 → 部署（**只到测试环境**）→ 自测 →（符合端到端场景时）端到端案例
   → 测试接手，提交 bug
   → 负责人定时取 bug → 判断清晰性
        ├ 不清晰 → PM 通知测试与负责人补充信息
        └ 清晰   → 派开发修复 → 再走 开发/部署/测试
   → 测试验证 OK 且临近上线
   → 上线准备（检视项 / DB 打包 / 资源注册 / 提单 / 版本完成发布）
   → 运维实施上线
```

### 边界

| 角色 | 负责 | 不负责 |
|---|---|---|
| 部署执行 | 发测试环境、轮询终态 | 生产上线 |
| 自测执行 | 测试环境验证、报告 | 端到端用例（符合场景时另派） |
| 测试（人） | 提 bug、验证修复 | 修 bug |
| 负责人 | 定时取 bug、判断清晰性、派修复 | 决定能不能上线 |
| PM | bug 信息不全时通知测试与负责人补充 | 判 bug 合不合格 |
| 上线准备 | 检视项、DB 包、资源、提单、版本完成发布 | 测试环境部署、修复 |
| 运维（人） | 实施生产上线 | — |

### bug 入口有两条

1. **主动拉**：负责人定时取 bug。
2. **被动收**：负责人或测试主动告诉 PM，PM 转给负责人修复。

### 召回

**复用旧会话**：召回后继续用原线程名的原会话，不新建。理由：上下文与历史都在，新建等于从零开始。

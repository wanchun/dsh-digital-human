# Spec: 数字人图标

Status: ready-for-agent

## Problem Statement

一个数字人可以有多个会话：企微单聊、群聊、每个需求一条线程、自测助手一条常驻会话。这些会话在列表里只有标题文字，没有稳定的身份标记。现在有三个数字人（PM、研发、自测），标题又经常是需求名或企微会话名，人很难一眼看出"这条会话属于哪个数字人"。

IM 绑定给了企微会话一个渠道图标，但那标记的是"从哪个渠道来"，不是"哪个数字人在干活"。数字人本身没有任何视觉身份。

## Solution

每个数字人可以可选地上传一个图标。会话行在标题前显示该数字人的图标；没有配置图标就不显示，保持今天的界面不变。

图标随记录保存（data URI），由用户自己上传、预览、清除；数字人列表也显示同一个图标。会话行的标题文字、自动命名、置顶逻辑都不变——图标只是标题旁的一个身份标记。

## User Stories

1. 作为维护者，我想给单个数字人上传图标，以便在列表里一眼认出它。
2. 作为维护者，我想在上传后先看到预览，以便确认选对了图片。
3. 作为维护者，我想清除已配置的图标，以便恢复默认的无图标状态。
4. 作为维护者，我想让图标默认是空的，以便不配置的人完全不受影响。
5. 作为维护者，我想让数字人列表显示同一个图标，以便列表和会话行看起来是同一个人。
6. 作为使用者，我想在会话行标题前看到数字人的图标，以便不点进去就知道是谁的会话。
7. 作为使用者，我想让已有会话自动带上图标，以便不用重新命名或重建会话。
8. 作为使用者，我想让没有图标的数字人保持原样，以便界面不被空占位撑开。
9. 作为使用者，我想让运行中的会话继续显示状态点，以便状态信息不被图标挤掉。
10. 作为使用者，我想让归档会话保持原样，以便列表不出现无意义的标记。
11. 作为使用者，我想让企微渠道图标继续显示，以便渠道身份不被数字人图标覆盖。
12. 作为使用者，我想让图标在导入导出后保留，以便换机器时身份不丢。
13. 作为维护者，我想让超过大小限制或格式不对的上传被明确拒绝，以便不用猜为什么没生效。
14. 作为维护者，我想让图标只接受本地图片数据，不请求外部地址，以便离线也能用。
15. 作为维护者，我想让图标以图片方式渲染，而不是把字符塞进标题，以便显示稳定、不依赖字体。
16. 作为使用者，我想让会话标题保持原样，以便搜索、重命名和标题置顶行为不被图标功能改变。
17. 作为维护者，我想在保存后立即看到列表更新，以便确认配置生效。
18. 作为使用者，我想让图标对所有会话一视同仁，不区分单聊、群聊和需求线程，以便身份标记一致。
19. 作为维护者，我想让图标数据随记录一起被校验，以便手工改坏的文件在读取时明确报错。
20. 作为使用者，我想在没有图标时完全看不到占位或破图，以便界面干净。

## Implementation Decisions

**记录的图标字段。** 记录新增一个可选的 `icon` 字符串：一个 data URI（`data:image/png`、`image/jpeg`、`image/webp` 或 `image/svg+xml`，base64 编码），空或未设置表示没有图标。校验在记录规范化时进行：前缀必须是允许的 data URI，长度不超过 64KB，否则报错。配置里只存 data URI，不存文件路径，也不接受远程 URL。

**落盘与打包。** 图标随 `config.json` 保存；导入导出按现有目录包携带，旧包没有该字段时视为空。旧记录不需要迁移。

**注册工具与设置接口。** 数字人注册工具新增 `icon` 参数（空字符串表示清除）；设置页的保存走现有 `registry.save` 接口，入参形状只多这一个字段。设置页增加"上传图标"控件：选文件、读取为 data URI、校验类型与大小、预览、清除；数字人列表与会话行共用这张图。

**会话行的渲染。** 客户端注册侧栏会话行的行首占位 `sidebar.session.row.leading`。占位拿到 `sessionId`，由宿主解析该会话的 `agentPreset` 再反查记录（preset 形态 `dh-<id>`），拿到图标后用 `<img>` 渲染（16×16，标题前留间距）；查不到记录或记录没有图标时不渲染任何东西。图标不写进标题、不调用改名、不 pin 标题。

**可见性。** 行首占位由侧栏决定：只在会话空闲时渲染，运行中显示状态点，归档行留空。这是本次接受的边界，不做"运行中也强制显示"的 DOM 增强。

**与 IM 图标的关系。** 企微渠道图标由 IM 插件挂在标题上（`::before`）；数字人图标走行首占位，两者位置不同、互不覆盖。IM 插件不在本次改动范围。

**会话到图标的映射。** 宿主新增一个小查询 `registry.sessionIcon`：按 `sessionId` 解析该会话的 `agentPreset`，再反查记录，返回图标或 null。不用会话列表做批量映射——列表摘要在这里拿不到 preset；逐会话解析与派活时走的是同一个 `resolveAgent`。客户端按 sessionId 缓存，记录变更时失效；行首占位不存在时静默降级，不影响设置页与其余功能。

**安全。** 图标用 `<img src={dataURI}>` 渲染，不使用 `dangerouslySetInnerHTML`；只接受 data URI，不发起外部请求；SVG 在 `<img>` 中不会执行脚本。

## Testing Decisions

好的测试只验证外部行为：一条记录能否带着合法图标存取、注册工具是否把图标写进记录、设置页是否能预览/清除、会话行在有图标/无图标时是否渲染出图片。不测 CSS 类名、DOM 层级细节或内部状态。

接缝（沿用现有测试位置）：

1. **存储的公共方法**：图标字段的规范化、读写往返、非法 data URI 与超限拒绝、旧记录缺字段视为空。现有存储单测覆盖同一位置。
2. **注册工具的 execute**：create/update 是否把 `icon` 放进 patch、空字符串是否清除、列表是否返回图标。用现有服务桩。
3. **客户端插件**：设置页上传/预览/清除，以及行首占位组件在有图标时渲染 `<img>`、无图标/非数字人会话时不渲染。沿用现有 jsdom 客户端测试的挂载方式，用桩按 sessionId 返回图标。

## Out of Scope

- 默认图标、图标库、emoji 回退。
- 运行中与归档会话强制显示图标。
- 修改会话标题文字或标题置顶逻辑。
- 远程图标 URL、图片裁剪/压缩编辑器。
- 每个会话单独配图标（图标属于数字人，不属于某条会话）。
- 改 DSH 核心或 IM 插件。

## Further Notes

- 上线需要重建宿主与网页客户端，并重启一次；图标只在前端渲染，宿主只负责存储与校验。
- 64KB 上限是为了让 `config.json` 保持可读、可 diff 的量级；超过就拒绝，不静默截断。
- 行首占位的可见性限制是侧栏既有行为，不是本次引入的缺陷；如果以后要"运行中也显示"，应另开一张卡做 DOM 增强或推动核心新增常驻占位。
- 现有三条记录初始都没有图标；自测助手需要的话由维护者上传。

# 11 · 派单只传事实，不传做法

Type: task
Status: open

## 问题

派单消息里塞了大量主观指令："你要先做 X 再做 Y""注意不要 Z""按这三步来"。后果有三：

1. 执行者不再判断——派单已经替它想好了；
2. 派单越写越长，上下文被指令占满，真正的事实反而被淹；
3. 同一件事在两处描述（派单 + 执行者的 playbook），必然漂移。

## 决定

**派单只传事实与上下文，不传做法。**

派单消息的结构化字段：

| 字段 | 说明 |
|---|---|
| requirement | 线程名与需求目录绝对路径（必填，07 已实现） |
| task_id | 工作项 id |
| node | 节点名，可空；空表示"由你判断" |
| facts | 子系统 / 版本 / 分支 / 环境 / 仓库路径 / 相关文档绝对路径 |
| context | 当前进度一句话 + 上一步结论的指针（不贴全文） |

禁止字段：步骤列表、命令、注意事项、"先…再…"这类过程描述。

**节点适用性由执行者判断。** 执行者有自己的 playbook，知道本角色该做什么、哪些节点对它有意义
（例如纯文档改动没有可运行行为，自测就没有对象）。跳过节点时，在回执与 state.json 里写理由；
负责人只校验"是否合理"，不预先规定序列。

## 验收

- 派单模板里没有步骤与命令（用一次真实派单核对）
- 执行者能自主跳过不适用节点，并在 state.json 留理由
- 负责人的回执校验只看结论与证据，不复述过程
- playbook 里"派单要说明步骤"这类表述全部删除

## 备注

旧数据里带字母的节点名（A 开发 等）按映射转中文，一次性处理。

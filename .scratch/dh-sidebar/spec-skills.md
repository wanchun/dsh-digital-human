## Problem Statement

技能的来源和可见性现在是三套并存：插件技能库可以上传、全局库有 86 个技能、记录里的 config.skills 是手填的名字数组。
配置页里只能「上传」，看不到「全局有哪些」，也看不出「当前勾了哪些」；而沟通协议 digital-human-comms 被当成可勾选的技能，取消勾选数字人就不会跟同伴说话了。

## Solution

技能只有一个来源：全局库 ~/.agents/skills。配置页列出全局全部技能，已勾选的高亮、未勾选的灰显，勾选结果写进 config.skills 作为白名单。
上传能力移除。digital-human-comms 内置进插件的操作上下文，不进库、不进列表、不进配置。新建记录默认全勾。

## User Stories

1. 作为组长，我想在配置页看到全局技能清单，以便知道系统里有哪些能力。
2. 作为组长，我想看到每个技能是否已勾选，以便判断这个数字人会不会某项能力。
3. 作为组长，我想勾选/取消勾选，以便精确控制每个角色能做什么。
4. 作为组长，我想新建记录时默认全勾，以便开箱能用、不用逐个点。
5. 作为组长，我不想再上传技能文件，以便技能只有一个来源。
6. 作为组长，我不需要关心数字人怎么跟同伴说话，因为那是插件的协议。
7. 作为维护者，我想未勾选的技能对该数字人的模型不可见，以便白名单真的生效。
8. 作为维护者，我想配置页在技能清单读取失败时给出明确错误，而不是静默空列表。
9. 作为维护者，我不想插件再维护第二份技能副本，以便改一处就生效。
10. 作为维护者，我想勾选状态存进记录本身，以便随 bundle 导出与迁移。

## Implementation Decisions

- 技能来源：只有 ~/.agents/skills；插件的技能库与上传路径删除。
- 新增只读 RPC：扫描全局库每个 SKILL.md 的 frontmatter，返回 name + description 列表。配置页用它渲染。
- 白名单：config.skills 是唯一开关；未勾选的技能由预设作用域的 provider 以同名影子屏蔽（modelInvocable=false），机制已存在。
- 默认值：新建记录时把全局技能全部写进 config.skills。
- digital-human-comms 内置：把通信协议（同伴地址、send/status/messages 用法、回执带 session_id、发送失败处理）并入插件的操作上下文；删除全局库那份；五份记录的 config.skills 移除它；勾选列表不显示它。
- 不做依赖校验：人设里的「依赖技能：…」保留为说明文字，插件不解析、不报错、不拒绝启动。
- 判定标准（写进文档）：一条规则若「不勾选就没法工作」，它属于机制，不属于技能。

## Testing Decisions

- 接缝只有一处：工具/服务层。
- 测：全局库扫描返回 name+description（含缺 frontmatter、空目录、坏文件）；白名单 provider 对未勾选技能返回影子且 modelInvocable=false；新建记录默认全勾。
- 客户端不做组件测试，配置页以沙箱实机验证（列表可见、勾选状态可见、取消后模型看不到该技能）。
- 先例：现有 tools.test / entry.test 的契约测试风格。

## Out of Scope

- 依赖校验与启动拒绝。
- 按角色预设默认勾选（已改为全勾）。
- 技能版本管理与升级。

## Further Notes

人设已重写为动作驱动：身份一句 + 我的动作（编号，含工具名）+ 回执模板 + 别人的事 + 边界。
人设点名工具是有意的——不点名时模型会自己找路（手写文件、绕开工具）。

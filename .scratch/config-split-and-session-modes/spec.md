# Spec: 数字人配置拆文件 + 会话模式

Status: ready-for-agent

## Problem Statement

维护一个数字人时，人设、机器配置、启用状态、IM 绑定全挤在一个 JSON 文件里。人设是一段 17KB 的字符串：改一句话看不出 diff，评审只能整段读，回滚只能靠记忆；手改这个文件还会被程序的下一次保存覆盖。人设是给人读、给人改的东西，机器配置是给程序读的东西，现在混在一起。

另一面，所有数字人只有一种会话方式：一个线程标识一条会话。研发助手按需求分线程是对的，但自测类数字人需要一条长期会话、任务排队进入；现在没有这个能力，只能每个任务开一条会话，列表越堆越多。

## Solution

把每条数字人记录改成一个目录：人设放可 diff 的 Markdown 文件，机器配置放结构化 JSON 文件，现有的记忆、会话索引、对话记录继续放在同一目录下。迁移一条命令完成，迁移后旧的单文件注册表删除，目录是唯一权威。

给记录增加一个"会话模式"：按线程（现状）或共享一条。共享一条的数字人只拥有一条长期会话，所有派活进入同一条会话并排队执行；会话建立时直接用记录名命名。默认保持按线程，现有数字人行为不变。

## User Stories

1. 作为维护者，我想把人设放在一个 Markdown 文件里，以便改一句话就能看到 diff。
2. 作为维护者，我想让人设的正文原样保存，以便现有的提示词不被改写。
3. 作为维护者，我想让人设的名称和描述只出现在人设文件里，以便避免两处不一致。
4. 作为维护者，我想让机器配置保持结构化，以便工具稳定读写。
5. 作为维护者，我想让"是否启用"属于机器配置，以便程序判断而不依赖人读。
6. 作为维护者，我想用一条命令完成迁移，以便不必手工搬运字段。
7. 作为维护者，我想在迁移前先预演，以便看到将要发生的改动。
8. 作为维护者，我想在宿主运行时被拒绝迁移，以便内存状态与磁盘不会打架。
9. 作为维护者，我想在迁移校验失败时原数据分毫不动，以便安全重试。
10. 作为维护者，我想保留一份迁移前的备份，以便回滚。
11. 作为维护者，我想让迁移后从目录重新合成的记录与旧记录逐字段一致，以便确认没有丢字段。
12. 作为维护者，我想让设置页的保存接口形状不变，以便前端不用重写。
13. 作为维护者，我想让导入导出仍然可用，并且能读旧格式的包，以便跨机器搬运不中断。
14. 作为维护者，我想让删除记录只删人设和配置、保留记忆与会话，以便历史不丢。
15. 作为数字人使用者，我想让研发助手继续一需求一会话，以便需求之间上下文隔离。
16. 作为数字人使用者，我想让自测助手只有一条常驻会话，以便会话列表不膨胀。
17. 作为数字人使用者，我想让共享模式下的第二个任务排队而不是打断当前任务，以便长任务不被打断。
18. 作为数字人使用者，我想让共享模式下的回执仍回到派活的会话，以便结果回到发起人。
19. 作为数字人使用者，我想让常驻会话建立时就有记录名作为标题，以便在列表里一眼认出。
20. 作为数字人使用者，我想让没有绑定机器人的数字人也能给自己的会话改名，以便整理列表。
21. 作为维护者，我想让并发保存串行化，以便设置页和工具同时保存时不丢改动。
22. 作为维护者，我想让未知字段在读取时被忽略，以便手写文件不能注入运行时不懂的状态。

## Implementation Decisions

**记录目录。** 每条记录一个目录，目录名即记录 id。目录内：人设文件、配置文件、记忆文件、会话索引、对话记录目录。后三者是既有状态，位置不变。

**人设文件。** 头部是仅有名称和描述两个键的元数据块，正文即原系统提示词，原样保存。解析器只认这两个键，不引入 YAML 依赖；正文里出现的分隔符不影响解析（只认文件开头第一组）。

**配置文件。** 包含：是否启用、工作目录、技能列表、同伴列表、IM 绑定（机器人 id、投递目标与负责人）、权限预设、是否保留记忆、订阅、自由配置、创建时间、更新时间、会话模式。记录 id 来自目录名，配置里不重复；名称与描述只放人设文件。

**权威与迁移。** 目录是唯一权威。迁移后删除旧的单文件注册表，另存一份带时间戳的备份，不做镜像。迁移逻辑放在存储层，命令行脚本只负责参数解析和"宿主是否在运行"的检查；宿主运行时拒绝迁移。迁移逐条写入，随后从目录重新合成，与旧记录逐字段比对；任一不一致即中止，原文件不动。

**启动兼容。** 只保留一个版本的兼容：目录为空且旧注册表存在时，明确提示先迁移，不再静默按旧格式运行。

**写入。** 先写配置、再写人设，各自用临时文件加改名，复用现有写锁。任一失败整体报错并保留旧文件。删除记录只删人设与配置两个文件，保留记忆、会话索引和对话记录。

**导入导出。** 以目录为单位打包，导入同时接受旧格式和目录格式。

**会话模式。** 记录新增字段，取值"按线程"（默认）和"共享一条"。按线程维持现状：每个线程标识一条会话，消息以插话方式进入正在跑的回合。共享一条：固定一条会话，所有线程标识只作为标签记录在消息头和往来说明里，消息以排队方式在回合结束后处理。共享一条首次创建会话时用记录名命名。不提供逐次选择插话或排队。

**标题工具。** 给会话改标题的工具不再依赖"是否绑定机器人"，没有机器人的记录也能使用。

**注册工具与设置页。** 注册工具新增会话模式参数；设置页新增一个下拉；其余入参与返回形状不变。

## Testing Decisions

好的测试只验证外部行为：读出来的记录、落盘的两个文件内容、投递到的会话和投递方式、工具返回。不测临时文件名、不测内部字段顺序、不测实现细节，重构后测试不应改写。

接缝（沿用现有测试位置，不新开）：

1. 存储的公共方法：读取、写入、删除、迁移。目录格式与迁移是这次的核心契约，迁移逻辑放在存储层，因此迁移也在这个接缝上测。
2. 会话投递的公共入口：会话选择与排队/插话方式。
3. 面向模型的工具：发送工具与注册工具的 execute，用服务桩驱动。

同类测试的既有先例：存储读写与索引的单元测试、会话投递的单元测试、工具参数与返回的单元测试、端到端装配测试。迁移用临时目录夹具：两条记录 → 执行迁移 → 重新读取 → 逐字段比对；失败路径断言原文件未动。

## Out of Scope

- 上下文压缩策略的调整、轮换、分段与交接（后续版本）。
- 企微单聊与群会话的创建和轮换（归企微插件）。
- 按记录裁剪工具或全局技能的硬边界。
- 旧注册表的镜像文件。
- 多上下文领域文档布局。
- 设置页的重做（只加一个字段）。

## Further Notes

- 上线顺序：停宿主 → 备份 → 预演 → 迁移 → 重启；代码改动需要重建宿主与网页客户端。
- 现有记录迁移后默认按线程，行为不变；共享一条由新建记录时选择。
- 迁移脚本需要网络无关、可重复执行（已迁移则直接退出）。
- 本地工单目录是草稿区，是否入库由维护者决定。
